# deploy/runpod — DVAS all-in-one RunPod deployment

Full plan: [`docs/DVAS_RunPod_Deployment_Plan.md`](docs/DVAS_RunPod_Deployment_Plan.md) ·
What was implemented on `runpod-v1` and why: [`/context_runpodv1.md`](../../context_runpodv1.md)

One container on one RunPod L40S pod runs every cloud service as a supervisord
program: nginx :80 (only public port), dashboard backend, ingest API, Keycloak,
7 analyzers + analytics gateway, PostgreSQL 16, Valkey, MinIO. State lives on the
network volume under `/workspace/dvas`.

```bash

deploy/runpod/tools/collect_versions.sh          # Phase 0 — needs the local stack running
deploy/runpod/tools/install_git_hooks.sh         # Phase 1.2
deploy/runpod/tools/dump_baseline_schema.sh      # Phase 1.3 — review, then commit
deploy/runpod/tools/stage_models.sh              # Phase 1.4 — commit models.sha256

# Phase 4.2–4.7 (RunPod console): docs/DVAS_Phase4_GHCR_Push_and_RunPod_Provisioning.md

```

Tests: `python -m pytest deploy/runpod/tests -q`

## GPU-aware analytics throughput (2026-11)

The analyzers detect the GPU and aim for **20–30 fps per drone** (every analyzer except crowd,
which stays at `CROWD_MAX_FPS`). Full notes: `context_gpu_fps.md` at the repo root.

- **GPU profile:** FP16 + cuDNN autotune on Volta+ (not GTX 16xx); drones per detector batch from VRAM
  (L40S 4, RTX PRO 6000 8). Override with `DVAS_FP16`, `DVAS_MAX_BATCH`. Inference sizes never change.
- **Newest frame only:** when an analyzer can't keep up it analyses the newest frame and acks the rest
  (shown as *skipped*), so lag stays at one frame.
- **Governor** (analytics gateway): if the GPU is ≥ 90 % busy and analyzers fall short, all of them
  are capped equally, never below the floor (default 5 fps). `GOVERNOR_ENABLED=false` disables it.
- **Detection Models page:** detected GPU, governor state, analysed vs input fps per analyzer and drone.
  SO/SA edit the target range (`PUT /api/models/performance/policy`, audited).
- **Valkey queue:** 2000 frames per drone, raw JPEG only (`QUEUE_WRITE_JPEG_B64=false`); ingest trims
  streams to a quarter when Valkey passes `QUEUE_MEM_GUARD_PCT` (85 %) of `maxmemory`.
- **Edge input:** the edge app sends 10 fps by default; raise its send rate to reach 20–30 fps.
- One tracker per drone now (they were shared across drones before), and anomaly loads its models once.

## Role & API audit changes (2026-11)

Fixes for `DVAS_ROLE_AND_API_AUDIT_COMBINED.md` and `DEAD_UI_FINDINGS.md` (edge pages excluded).
Things that change behaviour for operators, integrators and the DVAS Edge application:

- **Browser auth is cookie-only.** The login and refresh responses carry the access token only
  when the request comes from an origin in `EDGE_CLIENT_ORIGINS` (the Edge app). WebSockets accept
  `?token=` only on the handshake; services and the Edge app keep using `Authorization: Bearer`.
- **API docs** (`/docs`, `/openapi.json`) are off unless `DVAS_API_DOCS=1`.
- **Analytics stream control is POST-only:** `POST /api/analytics/<service>/stream/start|stop`
  (vehicle, anpr, crowd, person, intrusion, vessel, anomaly). GET returns 405.
- **Analytics services** require `X-Internal-Service-Key` on every route except `/health`.
- **Roles:** mission delete is senior officer / administrator only (409 if evidence or alerts
  reference it); audit sync (`POST /api/audit-logs/sync`) accepts only the caller's own rows,
  at most 500 per call, and re-chains them; `/api/edge/status` is removed; model deployment
  (`POST /api/models`) is senior officer / administrator; control room officers see models read-only;
  administrators cannot view evidence images; the full audit log is senior officer / administrator,
  others see their own entries; `/command/aggregated` and `/api/command/districts` are senior officer only.
- **New endpoints:** `/api/admin/{sessions,settings,policy,compliance}`, `/api/admin/users/{id}/logout`,
  `/api/audit-logs/aggregate`, `/api/infra/alerts/{id}/ack`, `/api/command/districts`,
  `GET /api/analytics/intrusion/config`, `/api/ingest-server/health/detail` (admin).
- **Settings** (Admin → System settings, table `system_settings`, applied by a startup migration):
  evidence, report-PDF and audit retention days and the daily retention job time (IST).
  Token lifetimes stay in Keycloak; TLS stays at the RunPod / Cloudflare edge.
- **NOC telemetry** shows only measured values; anything not instrumented is `null` ("—" in the UI).
